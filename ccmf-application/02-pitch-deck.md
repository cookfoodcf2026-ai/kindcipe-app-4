## Slide 2：問題 — 今晚食咩？

**核心問題**：香港家庭每晚面對的決策疲勞和溝通斷層

**數據點**：
- 香港 120 萬家庭住戶
- 35 萬外傭負責家庭煮食
- 每晚 30–60 分鐘浪費在「諗食咩」
- 等於每年 365 小時 = 45 個工作天

**用戶原話**：
> 「每晚花時間碌手機睇 IG 諗食咩，又要同工人講買咩」
> 「工人姐姐煮食溝通好麻煩」
> 「一家人最緊要係坐埋一齊食一餐飯」

**痛點總結**：
1. 決策疲勞 — 每晚重複思考食咩
2. 溝通斷層 — 僱主與外傭語言障礙
3. 情感連結流失 — 各睇各手機
4. 時間機會成本 — 365 小時/年

## Slide 3：解決方案 — 一站式晚餐作業系統

**產品定位**：
> 「一站式平台由決定食譜、營養價值，一鍵生成食材清單；見到中意嘅食譜直接 save 低。」

**核心功能**：

| 功能 | 說明 |
|---|---|
| 🤖 **AI 廣東話排餐** | 輸入屋企有咩人食，自動排好一週餐單 |
| 📸 **IG/YT 食譜匯入** | 貼上連結或截圖，AI 自動解析食材步驟 |
| 🛒 **智能購物清單** | 自動生成，一鍵跳轉 HKTVmall |
| 👨‍👩‍👧 **家庭共享** | QR Code 邀請家人，共享食譜和清單 |
| 🧑‍🍳 **工人模式** | 大字體、雙語、簡化操作 |

**品牌敘事**：
> 「當所有人都話手機有害，我哋會因為手機連結起來，共聚晚餐。」

## Slide 6：技術架構

**前端**：
- React Native (Expo SDK 54) + expo-router
- TypeScript + StyleSheet / React Query 5
- tRPC 客戶端 + React Query 5

**後端**：
- Node.js + Express + tRPC 11
- PostgreSQL + Drizzle ORM
- LLM 集成（DashScope）— AI 食譜解析、廣東話對話

**關鍵技術優勢**：
- 全端類型安全（tRPC end-to-end type safety）
- OTA 更新能力（Expo Updates）
- Serverless 部署準備（Railway/Render）

## Slide 7：市場機會

**TAM / SAM / SOM**：

| 層級 | 範圍 | 估算 |
|---|---|---|
| TAM | 香港 120 萬家庭住戶 | 無限 |
| SAM | 有智能手機的家庭 | ~100 萬 |
| SOM | 內測期目標 | 20–30 個 Beta 家庭 / 100 名高黏性用戶 |

**目標客群**：
1. **主要**：25–45 歲香港家庭煮食决策者（媽媽/主婦）
2. **次要**：僱用外傭的家庭（35 萬外傭對應家庭）
3. **長尾**：雙職父母、單身貴族、長者自炊

**競爭格局**：
- Cookpad、OpenRice：有食譜但無家庭協作和 AI
- 下廚神器：簡中為主，缺乏廣東話和香港本地化
- **Kindcipe 差異化**：廣東話 AI + 工人模式 + HKTVmall 整合
